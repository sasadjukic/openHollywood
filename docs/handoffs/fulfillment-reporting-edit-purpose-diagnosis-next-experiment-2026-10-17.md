### P1 notices correctly but confuses different reporting responsibilities

Every P1 duplicate-plus-overrun attempt identifies both the entry and the duplicate.
The boundary and native judgments are supported; both duplicate occurrences are
cited, with a minor craft finding and advice to remove one copy. Three distinct
contract obligations then matter:

| Obligation | What the responses did | Why it is invalid |
| --- | --- | --- |
| Who authors boundary advice | Three attempts put `repair_ref: boundary` in model-authored condition records | Boundary advice is already application-owned; `boundary` is a valid finding reference elsewhere but not a model-authored condition owner. |
| Who authors a boundary restatement's recommendation | The 19501 retry supplies a separate boundary recommendation | A linked restatement must use null and reuse the existing finding's advice. |
| Which findings independent craft must compare against | All four attempts leave the duplicate's comparison references empty | Independent means a distinct defect, not exemption from comparing it with the reported boundary finding. |

The duplicate's assessments say it is independent or unrelated. The contract asks
a more specific question: does that defect remain after correcting the entry?
Here it does. The model's wording is consistent with interpreting comparison
references as dependencies or shared ownership rather than required comparison
coverage. That is a plausible interpretation of the error, not access to hidden
reasoning. Likewise, reuse of `boundary` across different reference fields makes
namespace confusion plausible; the exact invalid fields are established facts.

**Offline correction exposes the concealed second error.** On all four response
copies, remove only the invalid application-boundary condition record and set any
linked boundary recommendation to null. Every copy then fails on the independent
craft comparison. Adding the missing `boundary` comparison reference makes all
four validate, retaining both issues and the original native/boundary judgments,
craft description, severity and evidence. No new craft finding or semantic verdict
was inserted. This establishes a reporting path that preserves the observations;
it does not establish that a model can produce it reliably or that structural
acceptance proves the adequacy of the comparison's explanation.

The current diagnostic enrichment cannot help these rejected responses:
`_critic_link_failure_details` first calls assignment-advice rendering. Rendering
fails on the ownership error and the helper returns no extra diagnostics. Both
actual retry requests consequently focus on the condition reference, repeat the
long general condition rule and omit the independent-comparison failure and
retained-classification metadata. The displayed reference shape is a bounded
string, not a concrete list of valid owners for this rejected response.

The 19501 retry removes the condition record but introduces separately authored
boundary advice; 19503 repeats the first error. Thus first-error feedback is an
identified bottleneck, **not a complete explanation or a guaranteed fix**. Even
the exposed rule was not consistently followed. A bounded test can determine
whether more specific simultaneous feedback helps before a larger schema redesign.

## Proposed A: expose the complete, independently checkable retry work

Use **eight full scenes at two new seeds, 19601/19603**: the existing six P1 cases
(base, duplicate and functional recurrence, each with/without overrun), plus the
previously sealed Elena missing-decision and compound-outcome controls. Those last
two require real native condition records. They prevent a candidate from appearing
successful simply by emptying every condition array. The compound case also tests
unmet native content alongside a boundary violation. Preserve each source's full
context, assigned semantics and immutable provenance.

Run one ordinary **P1 initial critic** per case/seed, for **16 initial calls**.
If it validates, the identical result is shared by both retry policies and no
correction calls occur. If it fails structurally, fork that same rejected response
into two isolated branches, each with exactly one correction call:

- **R0:** the existing ordinary retry request and diagnostics.
- **R1:** the same request, schema, semantic rules and full context, with a bounded
  set of concrete diagnostics for all independently checkable failures. Specifically
  cover valid model-authored condition owners, separately authored linked advice,
  and independent-craft comparison coverage when its current findings can be
  structurally established. Give exact locations and current permitted references;
  do not merely repeat the whole contract.

This tests one feedback bundle, not the independent effect of each diagnostic.
Both branches retain the current final validator and produce the entire review.
The collector never edits the rejected object into an accepted output, fills a
comparison, creates a condition, or certifies a semantic judgment. Unknown or
malformed dependencies cannot supply invented references. Any diagnostic-only
projection must be isolated from canonical outputs and writer-source eligibility.
Keep existing classification-retention safeguards; do not force an unvalidated
allegation to become true. Explain these distinctions in the later local tests.

Unlike the failed proactive route index, this is feedback tied to errors in an
actual response and its current findings. Unlike J1, it still must return the full
ordinary critic result, including craft. It changes neither the initial reading
task nor acceptance strictness. No corrected historical copy enters the live arms.

Counterbalance R0/R1 call order across seeds; both branches use the same rejected
input, seed and settings. Set critic temperature 0.2, top-p 0.95, thinking disabled.
There is **no second correction within either branch** and no correction for a
semantically wrong but valid review. Maximum A calls: **16 + 32 = 48**.

Proposed scoring, to freeze before execution:

- Keep first validity, final validity, valid supported native/boundary judgments,
  independent duplication detection, advice support and reference/classification
  drift separate. A dropped duplication issue is not a successful recovery.
- A useful R1 signal requires at least **two paired rescues** where R1 qualifies
  and R0 does not, including a duplicate-plus-overrun case, with no paired loss.
  Require all four duplicate cells to retain valid supported findings, both
  combined cells to qualify, all 16 native/boundary results to be valid and supported,
  and no unsupported repetition-removal demand on base/functional controls.
- Actual native repairs must remain present and supported in the Elena controls;
  no invented causality, timing, explicit narration or other extra obligation.
- If too few first responses fail, the retry comparison is **inconclusive**. Do
  not manufacture failures or spend unused calls on more seeds. Shared successful
  initials are not independent successes for two models or two fresh critic arms.

## Proposed B: make each selected edit accountable to its task

Hold exact-edit representation, full prose/context, original feedback, fulfillment
packet and sampling fixed. Use temperature **0.85** in both arms: 0.2 earned no
preservation advantage. Reuse the two fixed ordinary sources for separate and
embedded entry. Add one already valid P1 source for optional duplication repair:
`s19501-elara-duplicate-within-initial-P1`, attempt 1, from the completed run.

- **W0:** unchanged E1 exact-edit writer.
- **W1:** the same writer with a proposed structured purpose for each edit: reference
  its supplied repair test or selected optional craft issue, and briefly state the
  defect that would remain if the original selected text were kept. Distinguish
  direct repair from adjacent grammatical/flow adjustment needed by that repair.
  Evaluate whether the actual change follows that explanation.

This is a checkable editorial claim, not a request for hidden reasoning. Exact
wording/schema must be developed and frozen only after preparation is authorized.
The intervention combines that output field with its necessary instruction; it
does not isolate explanation length from task framing. Validate reference identity
and field shape, but score substantive justification separately. Fluent excuses
for needless changes count against W1; they do not become evidence of necessity.

Both arms may edit anywhere, including fulfilled evidence, and may perform a
justified broader change. No protected spans, automatic minimum-diff acceptance,
edit-count quota or fixed replacement phrase. No automatic trimming of returned
edits, semantic retry, extra self-critique call or patch repair by the application.
The original E1 atomic application and immutable base checks remain intact.

**Craft control:** the fixed source genuinely detects two adjacent copies with a
minor issue and a pass verdict. Both arms receive the same explicit diagnostic
request to address that optional craft issue. Preserve its original severity,
verdict, advice and citations; do not manufacture a mandatory repair test or imply
that production would automatically revise a passing scene. It is independent of
new A results and needs no live source lottery. Verify its lineage/projection during
preparation; inability to represent it honestly is a preparation blocker, not a
reason to fabricate evidence.

The control must remove the accidental repetition while retaining the bracing
action, indirect decision, boundary and unrelated scene. It prevents a preservation
strategy that refuses the supplied craft task. However, only one copy is positively
cited: deleting the other copy can succeed without editing positive evidence.
Report exact range overlap. **This does not qualify cases where a craft repair
necessarily changes fulfilled evidence**; that remains a separate open requirement.

Three fixed sources × two arms × two seeds = **12 writers**, each followed by one
unchanged ordinary P0 post-review if its patch validates: **24 primary probes,
maximum 48 calls** with one structural retry each. The post sees the materialized
scene and original feedback, not the edit-purpose statements; it cannot reward
W1's explanations. Posts remain factual checks, not preservation judges. Direct
full-prose inspection and blind pairs assess preservation and craft independently.

Provisional success requires all four W1 boundary repairs and both W1 optional
craft repairs, fulfilled facts retained, at least two clear preservation wins
among the four boundary pairs including an embedded case, and no preservation
loss in any of the six pairs. W1's stated purposes must be supported by the actual
defect and change; rationalization cannot satisfy the criterion. Treat invalid
outputs as failures, mixed/tie as non-wins, and no-op craft output as a failed
control. Record a sensitivity analysis neutralizing debatable additions. Do not
award literary superiority from these operator judgments or exact restoration.
