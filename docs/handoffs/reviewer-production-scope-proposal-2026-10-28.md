without changing its instructions or projection algebra.** It may instead fail

## Prospective scoring and interpretation

Freeze source gold, primitive statuses, exact scope inventory, witness alternatives,
whole-claim aggregation, thresholds and all denominators before inference. Mask
arm/family identities where feasible during inspection; the ledger format itself
can reveal PO, so inspection is not fully arm-blind. Inspect complete sources,
all primitive reasons, non-target components and whole claims. Seal notes before
decoding IDs. Do not use private thinking as semantic evidence.

Proposed useful-signal screen:

- **40/40 valid deliveries**, with invalid/terminal attempts retained in the
  denominators. No output repair or substitution.
- **20/20 usable PO targets:** all **60 primitive statuses** correct and grounded,
  correct source and event projections, adequate witnesses and supported reasons.
  A correct derived label with any wrong premise fails the target.
- Correct BS and PO historical incomplete-S controls; no false positive from entry
  time, assignment, incompatible authority, summaries or candidate claims. Every
  fresh class must pass in both orders for PO.
- **40/40 correct, grounded conditional controls**, using the fresh compatible-
  predicate negative gold; preserve the true assignment violations and qualified
  craft controls. No BS-to-PO protected loss on a shared non-target or target.
- Report actual matched BS-to-PO recoveries separately from alignment. If BS fails
  a target contemporaneously, PO must recover every such usable opportunity for
  the recovery screen. Do not count invalid BS output as a semantic opportunity.
  If no BS failure recurs, report alignment and transfer only, with the comparative
  recovery question inconclusive; do not manufacture a recovery requirement after
  seeing results.

Delivery, label accuracy, premise accuracy, source grounding, citation adequacy,
conditional discrimination and efficiency remain separate measurements. Inspect
whether a failure concerns relation semantics, source-role confusion, incomplete
review, coverage declarations or generation validity. Do not infer a cause from
a single family or interpret OR/RO calls as independent stories.

Record input tokens, combined thinking/final tokens, elapsed request time, and
resources per attempted and per usable report. Keep unreported reasoning/final
splits and actual billing unknown. There is no automatic latency qualification
or story-quality preference result. Even a clean result would justify retaining
generalization evidence and evaluating an adapter locally, not promoting PO,
rewriting production prompts or dispatching writer repairs.
