## Whole-claim aggregation: what it can and cannot do

The earlier audit already had a conjunction helper for authored annotations. This
work adds an isolated **response-boundary prototype**: an application-supplied
component specification, one required keyed assessment per component, and an
application-derived whole-claim label. It is not connected to a production role,
writer, graph or retry path, and has no live entry point.

For claims whose material assertions have been faithfully represented as a
conjunction, the proposed rule is:

| Supplied component judgments | Application-derived whole claim |
| --- | --- |
| Any unsupported component | Unsupported |
| None unsupported, but at least one uncertain | Uncertain |
| Every component supported | Supported |

Keep factual assertions, explicit constraints and literary interpretations
identified separately. A supported craft component means **defensible from the
complete sources**, not uniquely preferable or objectively proven. Unsupported
whole-claim status rejects that allegation as worded; it does not authorize a
manuscript rewrite or condemn every clause in the critique. Component results
remain inspectable even when one unsupported premise settles the whole label.

The prototype rejects missing, extra, duplicate or reordered component identities;
model-supplied whole-claim verdicts; extra response fields; duplicate JSON members;
unknown/duplicate references; definite judgments without evidence; and exceeded
evidence/reason budgets. Uncertainty may use an empty evidence list. It aggregates
labels only after complete structural validation; it never silently fills a
missing component or chooses among duplicate fields.

Three limits remain decisive:

1. **Recognized falsity can be enforced only if it is delivered explicitly.**
   MC-H-RO's explanation acknowledges consistent chronology but approves a
   substitute core. An explicit unsupported status-contradiction component would
   prevent an overall supported label. The current capture contains prose, not
   such a structured component result. The local mapping is authored; it is not a
   recovered model judgment or evidence of a live gain.
2. **Wrong inputs remain wrong.** N's false status contradiction and B's invented
   prerequisite are endorsed in the captured reasons. Aggregating equivalent
   supported component labels would still endorse the false claim. The prototype
   cannot distinguish obligation, intention and factual status by arithmetic.
3. **Decomposition and explanation remain semantic work.** Omitting a material
   false assertion from an otherwise complete specification can yield a spurious
   supported result. A correct claim label can coexist with a false craft
   rejection, as in MC-H-OR, or a new exhaustive count in its reason, as in MC-Q-OR.
   Tests explicitly demonstrate those limitations instead of treating structurally
   valid aggregation as source verification.

The 27-item inventory is an audit aid, not ready-made live input. Its short
annotations sometimes bundle assertions and do not prove complete decomposition.
Before a comparison, check component wording against each entire claim, retaining
negation, quantifiers, modality, attribution, version ownership, relational scope
and interpretive qualifications. Do not turn a conditional, disjunction or
comparison into an unrelated conjunction. Do not convert a false assertion into
its corrected counterpart while decomposing it. Exact claims and full sources
must remain visible alongside components; gold, rationales and source selections
used for scoring must remain withheld.

B/C03 and G/C03 still permit alternative scope readings. Their historical gold
remains unchanged, and neither becomes a clean primary factual target merely
because a component table is easier to score. No new human production checkpoint
or repeated literary review of near-identical samples is introduced.

The two nine-reference arrays are both B/C03 in RO, one per arm. These are
cardinality failures, not missing-source, duplicate-member, unknown-reference or
transport failures. The original output contract already asks for a smallest
sufficient set and uncertainty if the bound cannot support a judgment.

For each rejected capture, an **authored eight-reference representation** covers
the duplicate pair and remaining instance, revised discovery and decision, the
explanation wish, original no-alteration action and revised seam action. Original
discovery/decision retention is checked against the complete sources. This follows
the existing representative-citation policy; it does not require every incidental
observation to receive a separate citation. The demonstration passes the unchanged
structural boundary but does not establish that the secondary claim is true or
that the model can select the set reliably. It neither repairs the archived
response nor establishes a universally minimal evidence set.

**Retain the eight-reference bound for the next semantic comparison.** Do not
raise it simultaneously with decomposition, silently discard a ninth reference,
deduplicate a malformed response, or give invalid reports partial credit. A
separate cardinality-only comparison may later be justified if repeated evidence
shows adequate support cannot fit; this audit does not show that necessity.

For the component prototype, count the **union of distinct references across all
components of one claim**, with a maximum of eight. A reference may support more
than one component, but each component's own list must be distinct and valid.
This is not eight fresh references per component. Similarly, the **sum of reason
characters across components stays at most 2,000 per claim**, preserving the
current explanation allowance. The model must select the references; the
application only validates identities, resolves exact quotes and counts the union.
Semantic sufficiency and unsupported explanations still require source inspection.
